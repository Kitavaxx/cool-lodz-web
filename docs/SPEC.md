# Cool Łódź web: implementation spec

Based on `specyfikacja_strona_webowa` v0.3 and the decisions in [grill.md](grill.md). The source spec decides **what** we build. This file decides **how** we build it in this repository.

## 1. Goal

A hackathon demo that shows shaded walking routes, cool places and shade gaps in Śródmieście, Łódź. It must look good in the presentation and video and be honest about what we calculate. No backend: Python precomputes static files, and React displays them.

## 2. Glossary

| Term | Meaning |
| --- | --- |
| Sun share (`s`) | Part of a segment's length outside building shadow, 0 (full shade) to 1 (full sun) |
| Hour | One of `10, 12, 14, 16, 18` on 15.07.2026, Europe/Warsaw |
| Variant | Route computed with cost `length × (1 + λ × s)`: `shortest` (λ=0), `compromise` (λ≈1), `shaded` (λ≈3) |
| Cool place | Public indoor place to cool down (library, culture centre, gallery, office) |
| Accuracy | `szacunek` (buildings only) or `model` (exact heights and trees) |
| Shade gap | Segment with the highest sun share at 14:00 |
| Candidate | Public building ranked as a possible new cool place |

## 3. Stack

React 19 + Vite + TypeScript, React Router, MapLibre GL JS with OpenFreeMap tiles (`positron` style), Firebase Auth (e-mail and password), Firebase Hosting (project `coollodz`), GitHub Actions deploy (merge to `main` deploys live, a PR deploys a preview channel). Python (OSMnx, Shapely, GeoPandas, astral) runs locally in `scripts/`.

## 4. Structure

```
src/
  main.tsx        router and global CSS
  App.tsx         menu and routes
  firebase.ts     Firebase app and auth
  Panel.tsx       /panel: login, registration, panel views
  <Page>.tsx      one file per page, added when the page is built
  index.css       palette tokens and layout
public/data/      files generated by scripts/
scripts/          Python data pipeline
docs/             spec and decisions
```

Rule: one file per page. A shared module appears only when two pages need the same code (for example a `useData(url)` fetch helper or a map component).

## 5. Data contract

Python writes these files and the website only reads them. All files are in `public/data/` and are served from `/data/...`. Every file has a top-level `accuracy` and `computed_at` (ISO date) field. In GeoJSON these sit on the FeatureCollection.

| File | Feature / item | Properties |
| --- | --- | --- |
| `edges.geojson` | LineString | `id`, `s10`, `s12`, `s14`, `s16`, `s18` (0–1) |
| `routes.geojson` | LineString | `route_id`, `route_name`, `hour`, `variant`, `distance_m`, `time_min`, `sun_share`, `extra_min` |
| `places.geojson` | Point | `type` (`cool`, `water`, `bench`), `name`, `address`, `hours`, `source`, `verified` |
| `panel_gaps.json` | `{ items: [...] }` | `id`, `name`, `length_m`, `s14`, `geometry` (GeoJSON LineString) |
| `panel_candidates.json` | `{ weights, items: [...] }` | `name`, `address`, `score`, `no_shade_200m`, `dist_to_cool_m`, `summer_hours` |

`hours` uses the OSM `opening_hours` subset `Mo-Fr 10:00-18:00; Sa 10:00-14:00`. Places without hours are never "open now".

Walking time: 4.5 km/h. `extra_min` is the time difference compared with the `shortest` variant for the same route and hour.

## 6. Pages

### Required

| Path | Build | Done when |
| --- | --- | --- |
| `/` | Static sections: headline and "Otwórz mapę", heat banner ("dane symulowane"), problem with sources, 3 steps, methodology and limits, data sources, APK link and QR code (`qrcode.react`), panel link | All sections present, sources and limits described |
| `/mapa` | Full-screen MapLibre. Line layer from `edges.geojson`, coloured by `s{hour}`. Point layers for cool places, water, benches with toggles. "Cisza" and "Powietrze" are disabled buttons marked "w przygotowaniu". Hour buttons 10–18. Legend with percentages and accuracy label | Layers toggle without errors, changing the hour recolours segments |
| `/trasa` | Route select and hour buttons. Filter `routes.geojson` by route and hour, draw 3 variants in different colours and dash styles, comparison card. Cool places and water within 200 m of the route | Manufaktura → Piotrkowska shows at least 2 variants with different sun share |
| `/miejsca-chlodu` | List and mini map of `type=cool`, "Otwarte teraz" checkbox, nearest water, "Pokaż na mapie" link to `/mapa?place=<name>`, verified label | The "open now" filter follows the hours in the data |
| `/panel` | Login and registration form with a short offer for the city. After login: shade gaps (map and table), cool place reach (400 m circles), candidates (table with visible weights, "rekomendacja, nie decyzja") | Views are hidden until the user logs in |

### Optional, in this order

`/bezpieczenstwo` (text and links to GIS, IMGW, RCB), `/trasy-turystyczne` (`tours.json`), `/ranking` (`ranking.json`, "dane symulowane" label).

### Everywhere

Polish text. Works on phone and desktop. Never use colour alone: show a percentage or a label. One shared menu with every page. OSM attribution on every map.

## 7. Auth

- `onAuthStateChanged` in `Panel.tsx` only. `undefined` means loading, `null` means logged out.
- `signInWithEmailAndPassword` or `createUserWithEmailAndPassword`, switched by a toggle on one form.
- Password must be at least 6 characters, checked by the browser (`minLength`).
- Firebase error codes are mapped to Polish messages. Raw errors are never shown.
- Any signed-in user sees the panel. This is acceptable because panel data is static and has no personal data. It is on the limitations list.
- Authorized domains: `localhost`, `coollodz.web.app`, `coollodz.firebaseapp.com`.
- Out of scope: e-mail verification, password reset, roles, social login.

## 8. Build order

1. Auth module on `/panel` (login, registration, logout). **Done in this branch.**
2. Home page `/` (static, no data dependency).
3. `/mapa` with a hand-made sample `edges.geojson` and `places.geojson`, replaced when Python delivers.
4. `/miejsca-chlodu` (reuses `places.geojson`).
5. `/trasa`.
6. Panel views.
7. Optional pages.

Fallback cuts and extras follow spec section 8.

## 9. Limitations to publish

- Shade from building footprints only, with estimated heights. No trees in the base version.
- One summer day and 5 hours.
- 4 precomputed routes, no free A to B.
- Self-registration gives panel access in the demo.
- Heat banner and ranking use simulated data.
- AI use: Claude Code for code.
