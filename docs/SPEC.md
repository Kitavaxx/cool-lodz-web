# Cool Łódź web: implementation spec

Based on `specyfikacja_strona_webowa` v0.3 and the decisions in [grill.md](grill.md). The source spec decides **what** we build. This file decides **how** we build it in this repository.

## 1. Goal

A hackathon demo that shows shade on the walking network and cool places across the whole of Łódź, and shaded routes, shade gaps and the city panel in Śródmieście. It must look good in the presentation and video and be honest about what we calculate. No backend: Python precomputes static files, and React displays them.

## 2. Glossary

| Term | Meaning |
| --- | --- |
| Sun share (`s`) | Part of a segment's length outside building shadow, 0 (full shade) to 1 (full sun) |
| Hour | One of `10, 12, 14, 16, 18` on 15.07.2026, Europe/Warsaw |
| Variant | Route computed with cost `length × (1 + λ × s)`: `shortest` (λ=0), `compromise` (λ=0.3), `shaded` (λ=3). λ calibrated on the real network: with λ=1 the compromise mostly equalled the shaded route |
| Cool place | Public indoor place to cool down (library, culture centre, gallery, office) |
| Accuracy | `szacunek` (buildings only) or `model` (exact heights and trees) |
| Shade gap | Segment with the highest sun share at 14:00 |
| Candidate | Public building ranked as a possible new cool place |

## 3. Stack

React 19 + Vite + TypeScript, React Router, MUI (Material UI) with Material icons to match the mobile app, MapLibre GL JS with OpenFreeMap tiles (`positron` style), Firebase Auth (e-mail and password), Firebase Hosting (project `coollodz`), GitHub Actions deploy (merge to `main` deploys live, a PR deploys a preview channel). Python (OSMnx, Shapely, GeoPandas, astral) runs locally in `scripts/`.

## 4. Structure

```
src/
  main.tsx        router and MUI theme (colours from the mobile app)
  App.tsx         top bar, menu (bottom bar on phones) and routes
  firebase.ts     Firebase app and auth
  Panel.tsx       /panel: moderator login and panel views
  <Page>.tsx      one file per page, added when the page is built
public/data/      files generated by scripts/
public/img/       photos (hero, background) and screenshots of the site (step-*.webp, panel-reach.webp) for the home page; the screenshots are static, retake them when a page changes
scripts/          Python data pipeline
docs/             spec and decisions
```

Rule: one file per page. A shared module appears only when two pages need the same code (for example a `useData(url)` fetch helper or a map component).

## 5. Data contract

Python writes these files and the website only reads them. All files are in `public/data/` and are served from `/data/...`. Every file has a top-level `accuracy` and `computed_at` (ISO date) field. In GeoJSON these sit on the FeatureCollection.

| File | Feature / item | Properties |
| --- | --- | --- |
| `edges.geojson` | LineString, Śródmieście only, the default output of `shade.py`. The site no longer reads it: the shade tiles replaced it | `id`, `r` (street rank), `s10`, `s12`, `s14`, `s16`, `s18` (0–1) |
| `tiles/{z}/{x}/{y}.pbf` | Vector tiles of the whole city (layer `edges`), zoom 9–15, streets from zoom 10, sidewalks and paths from zoom 14. `tiles/empty.pbf` is the empty tile served for missing ones. A street's sun share is the length-weighted average of the sidewalks and paths within 25 m, because the centre line of a street is almost never in shadow | `s10`, `s12`, `s14`, `s16`, `s18` as whole percents (0–100), `d` (metres to the nearest cool place, straight line, capped at 9999) |
| `shares.json` | `{ items: [...] }` | `hour`, `shares` (share of street length in shade, half-shade and sun, summing to 1) |
| `reach.json` | `{ items: [...] }` | `reach_m` (400), `uncovered` (share of street length in the whole city farther than `reach_m` from every cool place), `cool_places` |
| `routes.geojson` | LineString | `route_id`, `route_name`, `hour`, `variant`, `distance_m`, `time_min`, `sun_share`, `extra_min` |
| `places.geojson` | Point | `type` (`cool`, `water`, `bench`), `name`, `address`, `hours`, `source`, `verified` |
| `panel_gaps.json` | `{ items: [...] }` | `id`, `name`, `length_m`, `s14`, `geometry` (GeoJSON LineString) |
| `panel_candidates.json` | `{ weights, far_m, items: [...] }` (`far_m`: distance at which the distance criterion is maxed out) | `name`, `address`, `score`, `no_shade_200m`, `dist_to_cool_m`, `summer_hours` |
| `tours.json` | `{ items: [...] }` | `id`, `name`, `description`, `hour`, `stops` (`name`, `coordinates`), `distance_m`, `time_min`, `sun_share` (shaded variant), `sun_share_shortest`, `geometry` (GeoJSON LineString) |
| `ranking.json` | `{ simulated: true, items: [...] }`, hand-written, `accuracy` is `dane symulowane` | `district`, `comfort` (0–100, higher is more comfortable in heat), `shade_share` (0–1), `cool_places` |
| `lodz.geojson` | Polygon | `name`; Łódź boundary from OSM, simplified to ~20 m. Maps cannot be panned outside the city and dim everything beyond it |

`hours` uses the OSM `opening_hours` subset `Mo-Fr 10:00-18:00; Sa 10:00-14:00`. Places without hours are never "open now". Addresses OSM lacks for some cool places come from `ADDRESS_FIXES` in `scripts/places.py` (the EC1 buildings share Targowa 1/3); `source` stays `OpenStreetMap`.

Walking time: 4.5 km/h. `extra_min` is the time difference compared with the `shortest` variant for the same route and hour.

## 7. Auth

- `onAuthStateChanged` in `Panel.tsx` only. `undefined` means loading, `null` means logged out.
- `signInWithEmailAndPassword` only. Login is a demonstration of the access flow. Regular users never need an account.
- The Firebase project (`coollodz`) is shared with the mobile app, so the user pool is shared too. The demo account is created by hand in the console and shown on the login card, so testers can try the panel. Its password is a throwaway one. Sign-up is not disabled there, because that would block the app. The website has no registration screen.
- Firebase error codes are mapped to Polish messages. Raw errors are never shown.
- Every signed-in account sees the panel, so no role check is needed in the demo. The login is not data protection: panel files are public static files. In the real version panel data moves to a database with security rules for the moderator role, and the panel checks the role (spec 7.1).
- Authorized domains: `localhost`, `coollodz.web.app`, `coollodz.firebaseapp.com`.
- Out of scope: registration, e-mail verification, password reset in the UI, social login.

## 9. Limitations to publish

- No medical advice on the site (a city mentor warned that health advice carries liability). `/bezpieczenstwo` gives facts and general rules from the RCB guide "Jak przygotować się na upał", each card names its source, a notice at the top says these are not medical advice, and the page links to IMGW, RCB and GIS. Only claims found in the guide are attributed to it.
- Shade from building footprints only, with estimated heights. No trees in the base version.
- Shade covers the whole city, but it is less accurate outside the centre: more detached houses and industrial buildings with a guessed 12 m height, and open ground where trees would give most of the shade. `/mapa` says so under the sun range buttons. Across the city about 88 % of street length is in the sun at 14:00 (almost all of it sidewalks and paths), which is higher than the centre because trees are missing.
- One summer day and 5 hours.
- 4 precomputed routes in Śródmieście, no free A to B. Of the panel views only the reach view covers the whole city, shade gaps and candidates are Śródmieście. The tourist routes too.
- The streets drawn at city zoom show the average of the sidewalks beside them (their own centre line is 98.6 % in the sun at 14:00). In July at 14:00 there is little shade anywhere, at 18:00 much more.
- Panel data is static files, readable without logging in by anyone who knows the URL. A database with rules comes in the next steps.
- Heat banner, ranking and 10 always-open test cool places ("Miejsce testowe 1–10", source `dane symulowane`, for testing the open state) use simulated data. Nothing else is simulated: shade, routes and panel views are our calculations on OSM data (`szacunek`), and cool places, water and benches are unverified OSM points. `/o-projekcie` ("Skąd są dane na stronie") explains the three kinds, and every place popup says its source and that it is unverified. Popups for water and benches say what the point is.
